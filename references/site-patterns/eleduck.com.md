## 平台特征
- 国内最早的远程工作社区，**不卡学历**，Node/React/AI 全栈需求密集，是大专背景候选人的友好入口。
- 两套独立系统，账号打通但资料分开：
  - `eleduck.com` —— 社区（发帖/评论/招聘频道），资料在 `/profile/info`，编辑在 `/profile/edit`
  - `talent.eleduck.com` —— **远程人才库**（雇主主动搜人），资料在 `/me/profile`，是引导式分步表单
- 社区用 antd，人才库用 **Semantic UI React**（`.ui.selection.dropdown`），选择器完全不同，别混用。

## 招聘频道 URL 模式（已验证）
`https://eleduck.com/jobs-channel?tags=<招聘类型>-<工作方式>-<城市>-<职业>-<领域>&page=N`
用 `0` 表示该维度不限。分页 `&page=N`（实测有 165 页）。

帖子列表提取：`a[href^="/posts/"]`，父级 row 的 innerText 含「发布于 N 天前 / 最后回复时间 / 回复数」，用来判断帖子是否还活着。**标题带「【已结束】」前缀的直接跳过。**

## ⚠️ 电量机制（决定你能不能真正申请）
- **「申请该职位」按钮扣 5 电量**；「查看他人联系方式」也是 -5。
- 新号电量来源实测：`用户注册 +2`、`完善资料 +2` = **总共 4 点，差 1 点就用不了申请按钮**。
- **但发评论是免费的**，且社区实际生态就是在评论区自荐——热门招聘帖下 20+ 条全是评论自荐，发帖人也在评论区回复。**优先走评论，不要为了点那个按钮去充电量。**
- 电量明细页 `/ele_records`，经验明细 `/exp_records`。

## ⚠️ 评论区禁止留联系方式
输入框 placeholder 原文：「请勿通过评论暴露联系方式，不符则删；**评论被删后，会扣除相应的电量和经验**」。
- 别放微信/手机/邮箱，**GitHub 等外链也有风险**。
- 安全写法：写「电鸭主页已完善（含 GitHub 和项目细节）」，引导对方看主页——站内链接（`https://eleduck.com/posts/xxx`）是社区通行做法，安全。

## 发评论与结果验证
- 编辑器：`textarea.input`（单个 textarea），用原生 setter 设值 + dispatch `input`/`change` 即可；提交按钮文字 `发布评论`。
- 提交成功的即时信号：**textarea 被清空**。
- ⚠️**别在帖子页里找自己的评论来验证**——评论区有分页/热度排序，新评论常不在首屏，`innerText.includes()` 会误判成"没发出去"。
- **唯一可靠验证：打开 `https://eleduck.com/profile/replies`（"我的评论"）**，最新一条在最上面，带「来自: <帖子标题>」。
  （注意不是 `/profile/comments`，那个 404 显示"对不起，什么也没有找到"。）

## 社区资料（/profile/edit）
- 字段：昵称、性别、个人简介、详细介绍、专业领域、职业身份、目前职位、所在城市、联系方式
- **「详细介绍」硬上限 300 字符**，超了保存时报「验证失败: 详细介绍过长（最长为 300 个字符）」。**先在本地数好字数再填**，反复试错很浪费。
- 用 label 文本定位：`[...document.querySelectorAll('.ant-form-item')].find(x => x.querySelector('label').innerText.trim() === '详细介绍')`

## 远程人才库（talent.eleduck.com/me/profile）
分 5 块，**引导式：基本信息不保存成功，后面四块全部锁死进不去**。
1. 基本信息 & 简历　2. 个人能力　3. 工作经历　4. 求职期望　5. 远程相关

### 基本信息
- 必填 7 项：姓名、工作经验、联系电话、**微信 ID**、邮箱、求职状态、可接受的远程薪资。
- ⚠️**微信 ID 必填且无法绕过**——代填时这是唯一必须找用户要的字段，提前问，别做到一半才发现被卡。
- 文本框：`input[name=name|phone|email|wechat|graduated_school|major|birthday]`，原生 setter 设值有效。
- `birthday` 默认预填**当天日期**（显示成 0 岁），务必改掉。
- 下拉是 Semantic UI，**选项没有 `data-value`，只能按 innerText 匹配**：
  ```js
  dd.click(); await sleep(300);
  [...dd.querySelectorAll('.menu .item')].find(o => o.innerText.trim() === '大专').click();
  ```
  dropdown 顺序：0=性别 1=求职状态 2=当前薪资 3=可接受远程薪资 4=工作经验 5=学历
- 简历上传：3 个 `input[type=file]`（中文简历/英文简历/作品集），**仅支持 PDF**。用 `/setFiles` 直接传，**独立于表单保存**，即使基本信息保存失败简历也能先传上去。

### 个人能力
- 职称水平下拉：初级/中级/高级/资深/专家
- 英语能力：4 行（听/说/读/写）× 4 档 radio —— **这是主观自评，代填时应该留给用户本人**，填错会直接影响海外岗推荐。
- **技术能力标签最多只能选 5 个**：标签是 `.tag-cloud .tag-cloud-tag`（span），选中后变成 `.ReactTags__tag` chip，删除按钮 `.ReactTags__remove`。
  - ⚠️**点中一个标签后它会从 tag-cloud 中移除并触发整片重排**，连续快速点击会大量丢失（实测 220ms 间隔点 12 个只成功 5 个）。**每次点击后 sleep ≥700ms 并重新 querySelector**，且点完要回读 `.ReactTags__tag` 核对。
  - 因为只有 5 个坑，**先想清楚哪 5 个最值钱再点**，否则得先删 chip 再补，而删除/新增操作本身也会丢标签（实测删 Android 时把 Node.js 一起弄没了）。
- 「个人介绍」textarea **上限 500 字**（提示写"少于 500 字"，实测 505 会被拒）。

### 完成度参考
基本信息保存后 70%，补完个人能力（职称+标签+介绍+作品）到 77%。
